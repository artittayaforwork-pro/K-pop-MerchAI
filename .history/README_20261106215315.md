## 4. How to execution all the notebook

> For this project, I used **Google Colab Extention - Colab Pro (paid product)** as GPU computing unit and **Google Drive** as Memory unit. Due to I faced laptop crashed because

The notebooks were developed in **VS Code with the Google Colab extension** and run on Colab GPUs.

1. Open the notebook in VS Code (Colab kernel) or upload it to Google Colab.
2. Choose a GPU runtime (see the table below).
3. Run `ENV_SETUP.ipynb` once to check the GPU, the shared settings and model access.
4. Run the notebooks **in order (1 → 4)**: **Run All**, and upload a data file when a cell asks for one.
5. Each notebook saves its results to `Results/` and, at the end, zips them to Google Drive (`MyDrive/Kpop_MerchAI/...`). Download and unzip the archive into `Results/`, because Colab files are deleted when the session ends.

- `SEED = 42` is used for every split, sample and image generator, so a rerun gives the same results (small GPU differences are possible).

## Implementation statement (per model pair)

### Pair 1: Trend Analysis (CLIP vs SigLIP 2)
- **Task:** zero-shot tagging of product images by colour and product type, then detection of rising items.
- **Method:** the tags feed a rolling-origin backtest, measured with precision@3 against a naive forecast. Colour labels are also tested in Korean and Thai, and occlusion saliency maps show which image regions drive each prediction.
- **Metrics:**
  - technical: tag macro-F1, precision@3
  - business: latency, cost, GPU memory
  - governance: multilingual gap
- **Outputs:** `Results/metrics/1_Trend_Analysis__{A,B}.json`, figures and tables. The rising colours and products feed Notebook 2.

### Pair 2: Design Generation (Lumina-Image-2.0 vs SDXL)
- **Task:** generate merchandise artwork from concept briefs.
- **Method:** each brief is a set of five products that should share one style. All three systems receive the same briefs, negative prompt and seed. A step sweep (1–30 steps) shows the speed and quality trade-off.
- **Metrics:**
  - technical: CLIPScore (prompt alignment), style consistency (mean pairwise CLIP image similarity)
  - business: seconds per image, cost, GPU memory
  - governance: commercial licence
- **Outputs:** `Results/metrics/2_Design_Generation__{A,B,baseline}.json` and image sheets.

### Pair 3: Global Pricing (GAT vs FAGCN)
- **Task:** classify each product into a budget, mid or premium price tier (tertiles of price in USD).
- **Method:** products are nodes with text, category, region and artist features, linked by same-artist and same-category graphs. Edge homophily is measured first. All three models are trained on two graphs with 5 seeds each (30 runs) and early stopping on validation macro-F1.
- **Metrics:**
  - technical: macro-F1 (mean ± std)
  - business: training time
  - governance: region F1 gap (US vs KR stores)
- **Outputs:** `Results/metrics/3_Global_Pricing__{A,B,baseline_mlp}.json` and `3_Global_Pricing__summary_by_graph.csv`.

### Pair 4: Comment Moderation (Granite Guardian vs Qwen3Guard)
- **Task:** decide whether each launch-day comment should be kept or removed.
- **Method:** each system gives a harm score from 0 to 1, read from the probability of the model's answer token, and a comment is removed at a score ≥ 0.5. A threshold sweep tests stricter settings.
- **Metrics:**
  - technical: F1, precision, recall, AUPRC
  - business: latency, cost per 1,000 comments, GPU memory
  - governance:
    - share of safe comments removed (limit 5%)
    - share of complaints removed
    - F1 gap across languages
- **Privacy:** emails, URLs and @handles are removed before any comment is shown or saved.
- **Outputs:** `Results/metrics/4_Comment_Moderation__{A,B,baseline_keyword}.json` and `4_Comment_Moderation__threshold_sweep.csv`.

## Responsible use

- No real artist's likeness is generated or processed. Generated content uses a fictional group, and Amazon images with a face are removed.
- The synthetic moderation comments use member roles (e.g. "the leader"), not names.
- Comments are shown and saved without emails, URLs or user handles.
- No tokens or keys are needed, and none are stored in the code or outputs.
- Course lecture slides and class notebooks are not included in this repository.

## Known limitations

- `QUICK = True` samples are small (for example, 330 comments in Notebook 4 and one seed in Notebook 2).
- Amazon labels come from product titles and are noisy; review counts are a proxy for sales; data ends in Sep 2023.
- Price data is a snapshot of listed prices, not sales; Korean stores are only 4% of products.
- The guard models were trained for chatbot prompts, so fan comments are a domain shift; Thai and English moderation data are synthetic.
- Results may vary slightly between GPUs; the GPU, time and library versions of each run are saved in every JSON file (`env`).
